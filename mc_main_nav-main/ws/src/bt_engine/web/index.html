The shape of a search

Ask the camera to start looking, run a search while it has not found anything, then drive to where it says the object is. The control flow is ordinary BT.CPP — ReactiveFallback re-checks the condition every tick and halts the search the moment it succeeds. 

<Sequence>
  <SetGripper position="0"/>
  <VisualizeObject object_name="the white paper cup"/>

  <Timeout msec="60000">
    <ReactiveFallback>
      <IsObjectFound object_name="the white paper cup"/>
      <Patrol/>
    </ReactiveFallback>
  </Timeout>

  <NavigateToDetectedObject standoff="0.05"/>
  <SetGripper position="100"/>
</Sequence>

Running it

Simulator on your laptop

Engine, mocks, map, fake robot and Nav2, on ROS_DOMAIN_ID=59, the same domain as the real robot — run one stack at a time.

./mc sim          # add "rviz" for RViz
./mc status       # what is running, plus a health check
./mc logs         # follow the robot side
./mc down

The camera service is a separate thing. Point the engine at it, or use the stub:

./mc shell engine 'ros2 param set /bt_engine camera.base_url http://<host>:<port>'
./scripts/fake_camera.py --find-after 10 --x 0.40 --y 0.20 --drift 0.03
Send a tree 
./mc validate examples/search_and_track.xml   # check without running
./mc run      examples/search_and_track.xml   # run and follow it
./mc nodes                                    # this palette, as XML
./mc cancel                                   # stop the running tree

Against the deployed engine instead of your laptop:

export BT_ENGINE_URL=https://mcpc.taile84e23.ts.net
export BT_ENGINE_TOKEN=<token>
./mc run examples/search_and_track.xml

Or straight over HTTP, which is what the LLM does:

curl -X POST "$BT_ENGINE_URL/execute" -H "X-BT-Token: $BT_ENGINE_TOKEN" \
     -H 'Content-Type: application/xml' --data-binary @tree.xml
curl "$BT_ENGINE_URL/status" -H "X-BT-Token: $BT_ENGINE_TOKEN"
Watch what it is doing 
./mc rviz                            # map, costmap, planned path, goal
./mc doctor                          # the whole chain at a glance
./Groot2-v1.9.0-x86_64.AppImage      # live tree, connect to localhost:1667

The obstacle map UI is on port 8081 of whichever machine runs it.

After changing code

Python needs only a restart; C++ (the engine) needs a build.

./mc build bt_engine
docker compose -f docker/compose.yaml --profile sim restart engine
./mc test            # 23 unit tests, then the end-to-end suite
Served by the engine from GET /nodes — exactly what the LLM is allowed to use.
