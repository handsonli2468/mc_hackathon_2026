# Robot Brain v6.1.0

## Automatic BT Engine node synchronization

- Agent startup/restart now synchronously calls `GET /nodes?builtin=0` whenever `BT_ENGINE_ENABLED=1`.
- The old opt-in `BT_ENGINE_SYNC_NODES_ON_START` behavior is replaced by automatic startup sync. Emergency/offline opt-out: `BT_ENGINE_SKIP_STARTUP_NODE_SYNC=1`.
- Manual `POST /api/bt-engine/sync-nodes` remains supported and is serialized with startup/manual sync via an async lock.
- The last attempt is persisted to `state/bt_node_sync.json` and exposed at `GET /api/bt-engine/sync-status`, `/health`, and `/api/info`.
- Node-contract writes are backed up under `agent-runtime/config-backups/`; unexpected post-write validation failure rolls back to last-known-good files.

## Formal contract + semantic overlay

- Every custom node exported by the BT engine is parsed, including Action, Condition, Control/Decorator nodes and input/output/inout ports.
- Live IDs, kinds, port names, port types and defaults are authoritative and stored in `config/bt_engine_registry.generated.yaml`.
- Planner-only knowledge is stored in `config/bt_engine_semantic_overlay.yaml`.
- `config/skill_registry.yaml` is generated by merging live formal contracts with reviewed semantics.
- New leaves without semantics are formally ingested but quarantined from Planner/RAG. A review scaffold is generated at `state/bt_engine_semantic_overlay.missing.yaml`.
- Invalid semantic ports and unavailable verification dependencies are quarantined transitively.
- Existing v6.0.x semantic metadata is migrated from the legacy skill registry on first startup.

## RAG safeguards

- Scene RAG uses explicit user-message entity terms as hard anchors. LLM-expanded target descriptions are only a fallback when the user message has no usable English entity anchor.
- `pattern:human_clarification` is suppressed unless requirement extraction actually reports missing user information / `NEED_MORE_INFO`.

## BTGenBot phase compiler

- Adds conservative pre-validation sanitation for Markdown fences, bare `BehaviorTree` wrappers, `TreeNodesModel`/`include` metadata, and deterministic-policy wrappers.
- No required leaf is invented by sanitation; strict phase validation still decides acceptance.
- Compiler phase diagnostics now retain per-attempt sanitization changes, warnings, validation errors, and acceptance state.
